# Game Design Principles (GDP)

6 条设计原则，贯穿 Skill A 全流水线。**GDP 是软约束**：违反不阻塞流水线，但会在 GDD 中生成「设计风险标记」，提醒后续团队关注。

---

## GDP-001: MVP = 核心体验闭环

**原则**: MVP 的边界不是"最少功能"，而是"能让玩家完成一次完整满足的最小集合"。

**测试方法**: 
用 30 秒循环 + 5 分钟循环检验——如果砍掉某个 P1 模块后，玩家在一次完整 session 中无法体验到「刺激→决策→行动→反馈→满足」的闭环，则该模块不可砍。

**实践中的表现**:
- ✅ 保留战斗系统 + 成长系统 = 玩家打一局能变强 → 闭环完整
- ❌ 只保留战斗系统但砍掉成长 = 玩家打完一局没有任何变化 → 闭环断裂
- ✅ 砍掉社交排行榜 = 单人体验闭环不受影响 → 可以延后

**违反 = 风险标记**: 
`⚠️ GDP-001: 当前 MVP 可能不构成完整体验闭环——[具体哪个环节断裂]`

## GDP-002: 核心循环独立原则

**原则**: 30 秒循环本身必须好玩，不依赖 meta-game（成长、收集、社交）才能产生乐趣。meta-game 放大乐趣，但不创造乐趣。

**测试方法**:
假设去掉所有成长数值、收集进度、排行榜——只剩下 30 秒循环本身。问：「新玩家第一次玩这 30 秒，会不会觉得有趣？」如果答案是"不会，必须玩到有了一定积累才好玩"，则违反此原则。

此外，30 秒循环必须包含「决策→反馈」闭环——玩家必须在循环内做出有意义的选择并立即看到结果。

**实践中的表现**:
- ✅ Slay the Spire：每张牌的出牌决策本身就有策略乐趣，即使没有 deck-building
- ❌ 某些放置类游戏：30 秒内唯一操作是点击领取奖励，乐趣完全依赖积累
- ✅ 俄罗斯方块：第一秒就好玩，速度提升只是放大

**违反 = 风险标记**: 
`⚠️ GDP-002: 30s 循环缺乏独立乐趣——[具体缺失什么：无决策 / 无即时反馈 / 依赖外部数值]`

## GDP-003: 会话模式适配原则

**原则**: 会话模式（碎片化可中断 vs 连续沉浸式）由玩家行为驱动，不由平台硬性决定。设计时先定义玩家的典型游玩场景，再选择匹配的会话模式。

**测试方法**:
描述目标玩家的典型游玩场景（通勤地铁？沙发长时间？课间 5 分钟？），然后验证：5 分钟循环的长度和中断点是否适配该场景？如果场景是"通勤地铁"但一局要打 40 分钟，则不适配。

注意：同一平台上也可以有不同会话模式。手机可以有沉浸式体验（原神手游版），PC 也可以有碎片化玩法（迷你游戏合集）。关键是玩家行为，不是平台。

**实践中的表现**:
- ✅ 明确标注"目标场景：通勤碎片时间" → 5min loop 设计为可随时安全中断
- ✅ 明确标注"目标场景：周末长时间沉浸" → 允许 30min+ session 但提供存档点
- ❌ 只写"手机 = 碎片化"但没分析实际玩家场景 → 过度简化

**违反 = 风险标记**: 
`⚠️ GDP-003: 会话模式缺乏玩家场景支撑——[平台假设替代了行为分析]`

## GDP-004: 差异化可感知、可描述、可验证

**原则**: 游戏的核心差异化点必须满足三个标准：
1. **可感知**: 玩家在前 5 分钟内就能体验到（不是隐藏在后期内容中）
2. **可描述**: 能用一句话讲清楚（"这个游戏和 X 不同在于 Y"）
3. **可验证**: 有明确的方法判断差异化是否成立（可以是 playtest 指标、A/B 测试、或用户反馈问卷）

MVP 阶段聚焦 1-2 个差异化点，不贪多。

**测试方法**:
对每个声称的差异化点，逐一回答三个问题。三个都能回答 = 通过。任何一个回答不了 = 需要修正。

**实践中的表现**:
- ✅ "三国阵法系统"：可感知（第一局就摆阵）、可描述（"用武将牌组阵法触发技能"）、可验证（A/B 测试：有阵法 vs 无阵法的留存差异）
- ❌ "更好的画面"：可感知但不可验证（什么标准算"更好"？）
- ❌ "创新的经济系统"：不可感知（要玩到后期才看到），前 5 分钟体验不到

**违反 = 风险标记**: 
`⚠️ GDP-004: 差异化点 [X] 未通过三标准——[哪个标准失败 + 原因]`

## GDP-005: 假设透明 + 验证方法

**原则**: 设计中的每一个假设都必须被显式记录，并附带验证方法。假设不是缺陷——隐藏的假设才是。

**测试方法**:
扫描 GDD 全文，任何以"玩家会..."、"市场上..."、"大多数用户..."开头的陈述都是假设。每个假设必须有：
1. 假设内容（清晰陈述）
2. 推理依据（为什么做这个假设）
3. 验证方法（如何证实或证伪：playtest / 数据分析 / 竞品比较 / 用户访谈）

**实践中的表现**:
- ✅ "假设：目标用户习惯碎片化游玩（依据：同品类竞品数据）→ 验证：内测观察平均 session 时长"
- ❌ "玩家喜欢收集武将"（无验证方法，无依据）
- ✅ "假设：阵法系统增加策略深度（依据：TFT 的站位系统验证了空间策略有吸引力）→ 验证：playtest 中观察玩家是否主动尝试不同阵法"

**违反 = 风险标记**: 
`⚠️ GDP-005: 存在未标注的隐含假设——[具体假设内容]`

## GDP-006: 体验意图显式化

**原则**: GDD 中的每个 MVP 模块卡片必须显式声明三个体验设计字段，使下游架构师能读取设计意图而非自行猜测：
1. **核心决策** (1-3 个): 玩家在此模块中做出的最重要的选择
2. **爽点时刻** (1-2 个): 玩家感到满足/兴奋的具体瞬间
3. **策略空间**: 是否存在多种有效策略？还是只有唯一最优解？

**测试方法**:
检查每个 P0/P1 模块的 detail card 是否包含这三个字段。字段不能为空或泛泛而谈（如"让玩家觉得好玩"不算有效的爽点时刻描述）。

**为什么需要这个原则**:
Skill B（模块架构师）需要从 GDD 中读取体验设计意图来评估技术方案的可实现性。如果 GDD 不显式声明这些，架构师要么自己猜（可能猜错），要么忽略（设计意图丢失）。GDP-006 确保 Skill A → Skill B 的信息传递完整。

**实践中的表现**:
- ✅ 战斗模块：核心决策 = [出牌选择, 阵法站位]；爽点时刻 = [连锁阵法触发时的视觉爆发]；策略空间 = 多流派（速攻/控制/阵法）
- ❌ 战斗模块：只列了功能点（"支持回合制战斗"），没有任何体验设计声明
- ✅ 探索模块：核心决策 = [路径选择（风险/收益权衡）]；爽点时刻 = [发现隐藏区域的惊喜感]；策略空间 = 路线规划

**违反 = 风险标记**: 
`⚠️ GDP-006: 模块 [X] 缺少体验意图声明——[缺失哪个字段]`

## GDP 在流水线中的检查点

| Phase | GDP 检查 |
|---|---|
| Phase 0 (品类解析) | GDP-005: 假设是否已标注？ |
| Phase 1 (核心循环) | GDP-002: 30s 循环独立性检验; GDP-003: 会话模式是否有场景支撑 |
| Phase 2 (系统拆解) | GDP-001: MVP 闭环检验; GDP-004: 差异化三标准; GDP-006: 模块卡片体验意图 |
| Phase 3 (GDD 组装) | 全部 GDP 汇总检查，生成风险标记汇总表 |
